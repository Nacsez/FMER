# CPU optimization: 735-r9

24 October 2026. Local development branch `release/next-package-compat`.
Malachite is the only authorized development target. Published 734 downloads,
Citrine and Amethyst are unchanged. No push, merge or publication.

## Objective and retained contracts

Recover processing time without reducing six-voice synthesis, four independent
mono tracks, effects, screen updates, modulation resolution or output quality.
Keep the 44.1 kHz sample rate, 128-frame block, 2902 us block period, 2600 us
publication guard and strict 2177 us measured reserve threshold unchanged.
The active-voice transition correction from r4 remains enabled.

The r4 workload left insufficient reserve: six VA notes with all effects reached
2182 us, repeated six-note VA chords reached 2257 us, and four-track playback at
480 BPM with effect edits reached 2578 us. These were bounded observations with
no new late-block faults; they were not release timing passes.

## Implementation

* Inline the VA sample renderer so every sample of every voice avoids its
  register-save/call/restore overhead. Oscillators, envelopes, filters, LFOs,
  voice allocation and arithmetic formulas are unchanged.
* Force inline the small IEEE finite-value and effects helpers that the pinned
  pi32v2 compiler previously left as per-sample calls. NaN/infinity protection,
  denormal handling, output protection and diagnostic counters remain intact.
* Place `Effects::process` in the existing `.ram_text.dsp` area. Startup already
  copies that section from flash before enabling interrupts. The effects loop
  consequently avoids repeated flash instruction fetches while audio runs.
* Use the compiler's normal indirect member-function ABI once per block to
  call the RAM entry point. This avoids pi32v2's direct-branch distance limit;
  no hand-encoded branch or unverified compiler option is required.
* Keep a 400-byte validation memo separate from live controls. Previously
  accepted values need no repeated range check on each FX edit. Every changed
  value still uses the canonical validator, and cross-field constraints still
  run every time. Repeated invalid batches cannot poison the memo. It is owned
  by the existing single DSP thread and never changes a saved record.
* Unroll the fixed four/eight-element phaser and reverb loops with a hint for
  the pinned target compiler. This exposes constant indices and removes loop
  bookkeeping while preserving sample, stage and summation order. Other
  compilers keep ordinary loops; no floating-point reassociation is requested.
* Make the audio control handoff scan pending bit-mask words rather than all
  198 fields twice. Explicit values are still checked before intermediate
  selections, and the DSP setter validates the complete merged batch. The
  redundant second whole-batch validation is removed; recording-aware merges,
  cursor clamping, bank selection order and stale-budget protection remain.
* Precompute MSFA's 100 legal fine-tuning offsets once, before audio starts,
  using its original double-log/floor expression and the same target runtime.
  Notes reuse the exact rounded Q24 values. A 404-byte static cache replaces
  repeated software double-precision logarithms on operator note attacks.
  There is no new tuning approximation, callback initialization or allocation.

The new `core/target_hot.hpp` expresses these target-only choices. Desktop
processing remains ordinary portable C++. No allocation, logging, locks, flash
operations or additional buffers were added to the audio path. No fast-math,
clock increase or reduced-quality mode was introduced.

RAM routines here execute only while flash is readable. They are not substitutes
for the separate flash-busy-safe HAL routines. Synth rendering remains in XIP
flash; moving both renderers exposed out-of-range calls in the target linker.
Those builds failed before any hardware write. The compiler advertised
`-mlong-calls` but reported it unused for this target, so it was not adopted.

## Memory tradeoff

| Section | 735-r4 bytes | 735-r9 bytes | Change |
|---|---:|---:|---:|
| XIP `.text` | 226212 | 221172 | -5040 |
| Executable `.ram_text` | 2840 | 9200 | +6360 |
| Initialized data | 2084 | 2084 | 0 |
| BSS | 82508 | 83312 | +804 |
| Audio allocation pool | 294912 | 294912 | 0 |
| Workspace | 44272 | 44272 | 0 |
| Retained diagnostics | 76 | 76 | 0 |

The existing 24576-byte executable-RAM reservation has 15376 bytes free.
Nothing is borrowed from the audio pool, framebuffer, working state or stack.
Combined loaded code grows by 1320 bytes: code placed in RAM still needs its
startup copy stored in flash. This is a speed/placement optimization, not a
claim that executable code no longer occupies flash.

## Regressions and reproducibility

The same desktop compiler with `FMER_DEVICE` arithmetic produced bit-identical
before/after PCM and state across 104 synth scenarios, including all 32 FM
algorithms, both engines, mixed parts, factory voices, glide, ownership changes,
panic and variable block boundaries. The complete synth probe SHA-256 is
`962508ab9b20a78959238b162d55325ffeedc2bc0e77c6eec7314cdf374d7101`.

The new `tests/effects_pcm_probe.cpp` exercises all 720 effect orders, changing
parameters, bypass/reset, multiple models, variable blocks and invalid-input
recovery. Before/after files are identical, including PCM, meters and activity:
41379840 bytes, SHA-256
`c27ebe0ce559ce0b5e45c7e2900d6f97d13550c50ea612244a1aff965b344c70`.
These comparisons establish same-compiler arithmetic equivalence; they do not
claim that MSVC output is bit-identical to pi32v2 output or prove board timing.

The normal CTest baseline now includes synth and effects suites compiled with
device arithmetic. This exposed a stale phaser reference fixture: it expected
0..100% wet while the production control intentionally spans 0..50% wet. The
oracle now uses the documented half-wet scale. Its accuracy tolerance was not
relaxed, and the previous production implementation passes the corrected test.
The board-adapter regression also repeats invalid edits across every applicable
parameter and checks complete native-state preservation, plus individually
valid cursor/length values that form an invalid combination. Range-check reuse
does not bypass those relationship checks.
The real control-mailbox/adapter suite also rejects a malformed non-dirty
snapshot without changing native state. All earlier recording, bank-change,
cursor and stale-budget tests retain the same expectations.

The tuning test compares 12,288,000 combinations of note, ratio/fixed mode,
coarse/fine tuning and detune against the uncached implementation. Repeated
initialization and the out-of-range fallback are also checked. The 104-scenario
synth PCM/state hash remains identical after this change. Original MSFA hashes
were verified before updating the local patch and provenance records; its
Apache-2.0 notices and upstream commit remain unchanged.

The first full run passed all 36 CTest suites, but its Python suite observed a
mixed revision: it had imported the r4 profile definitions before the catalog
was updated to r5. Its package-availability test correctly failed. The complete
baseline is rerun against the stable final catalog; this failed run is retained.

Raw profiling, failed-link experiments, map, exact-output comparisons, backups
and hardware procedures are retained under ignored `artifacts/cpu-735-r5/`.
Private backups and audio are not distributed in the source or Companion.

Intermediate r5/r6/r7 were retained as failed-reserve experiments: dense
four-track peaks were 2373/2334/2309 us. The control handoff change in r8 reduced
that case to 2135 us, passing the unchanged gate. All twelve r8 six-voice cases
also passed (maximum 2021 us). No new audio faults were observed. The final
candidate adds the tuning cache and is judged from its own measurements below.

## Target qualification

Malachite runs the final 735-r9 candidate. Application-only installation used
the production Companion with reviewed layout guards and full pre/post backups.
All 128 instrument slots, five projects, MIDI configuration and personal FX
order match. Complete live RAM state was restored. The final smoke check
advanced 1730 audio blocks with no fault delta; all MIDI/audio clients closed.

| Workload | r4 peak | r9 peak | Reduction |
|---|---:|---:|---:|

| Repeated six-note FM chords, all effects, no in-loop polling | 2071 us | 1869 us | 9.8% |

| Four tracks, 480 BPM, all effects and live edits | 2578 us | 2141 us | 16.9% |

All twelve final FM/VA × dry/all-effects × 1/4/6-note cases passed the strict
2177 us gate. Dry rapid note replacement measured 480 us in 4T and 636 us in 6V.
Sustain, release/panic and 138 steals per repeated-chord engine were checked.
No new overruns, load sheds, rejected messages, MIDI overflows, LCD timeouts,
retained crashes or protective pauses occurred. The heaviest measured case
leaves 761 us of the 2902 us period (26.2%), including 36 us beyond the required
reserve. These peaks are bounded bench observations, not worst-case guarantees.

Two final 90-second USB captures each delivered 3,969,024 stereo 16-bit frames
at 44.1 kHz, with substantial nonzero note signals. Acquisition used the exact
Windows `Line (FMER Test01)` endpoint outside restricted agent execution.
This verifies acquisition and runtime continuity; it does not prove every
waveform is artifact-free or qualify the built-in speaker/analog output.
